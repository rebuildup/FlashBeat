# FlashBeat Web Studio

Standalone web app for the festival build. The Unity project is a separate
application and is never moved by this app.

Void (native routes + pages) · Vite+ · React 19 + TypeScript · Panda CSS · Park UI
(Ark UI) · lucide-react.

## Run it

```sh
vp install     # installs deps, runs `void prepare` + `panda codegen`
vp dev         # http://localhost:5173
vp check       # oxfmt + oxlint
npx tsc --noEmit
npx vitest run # unit tests
vp build
npm test       # database tests (node --test tests/)
npm run test:e2e          # Playwright browser E2E (seeds local D1 + boots vp dev)
npm run test:e2e:harness  # Vitest unit tests of the E2E harness logic
```

The browser E2E is the quality gate (`npm run test:e2e`, Chromium, real HTTP,
isolated local D1): it fails — rather than skips — when the browser is missing,
the server does not start, or no test is collected. See
[`tests/e2e/README.md`](tests/e2e/README.md) for the suites, the gate
self-check and the production harness.

### Database

```sh
void db generate   # regenerate db/migrations/ after a schema change
void db migrate    # apply pending migrations to the local D1
void db seed       # reset the local D1, re-apply migrations, run db/seed.ts
void db status     # applied/pending migrations
```

`songs`, `chart_versions` and `scores` follow `contracts/openapi.v1.yaml`; the
contract's limits are SQLite `CHECK` constraints. The migration is applied to the
FlashBeat D1 database with the official `cf` CLI — see
[`docs/operations/d1-migrations.md`](../docs/operations/d1-migrations.md).

`styled-system/` is generated by Panda and gitignored.

## Chart editor

`/chart` is the eight lane chart editor (issue #18). It reads and writes the legacy
FlashBeat chart JSON, draws the grid with `react-konva` and previews the song with the
YouTube IFrame API. It needs no backend: it opens with a real chart of the Unity
project and can be used before the publish API exists.

![chart editor 1280x720](docs/screenshots/chart-editor-1280x720.png)

## Publish screen

`/publish` is the publish screen (issue #19). It shows the metadata of one song next
to the chart editor and publishes both in one `PUT /api/v1/admin/songs/{songId}`.

![publish 1280x720](docs/screenshots/publish-1280x720.png)

The staff token is typed by the operator in the confirmation dialog. It stays in the
memory of the browser tab, is never written to disk and is never part of the bundle.

![publish dialog](docs/screenshots/publish-dialog-1440x900.png)

Broken fields are marked while the operator types, and the answer of the API is
shown next to the publish button.

![publish validation](docs/screenshots/publish-validation-1440x900.png)

![publish success](docs/screenshots/publish-success-1440x900.png)

### Where the request goes

The studio and the API are served by the same worker, so the screen publishes to the
API of the current origin: the request goes to `/api/v1/admin/songs/{songId}` of the
host the studio was loaded from and lands in the D1 of that deployment. The header
shows `Live API (this origin)`.

`VITE_FLASHBEAT_API_ORIGIN` moves the request to another origin. The value is a
public URL, the staff token is never part of it:

```sh
VITE_FLASHBEAT_API_ORIGIN=https://api.example.com vp dev
```

The API of the festival build sends no CORS headers, so another origin only works
when that origin allows the request.

`VITE_FLASHBEAT_API_ORIGIN=fixture` switches the screen back to the fixture in
`src/lib/publish/mock.ts`. The fixture answers like the contract does: same path,
same bearer token, same `401` / `422` / `200` answers, and it rejects a chart that
breaks the frozen chart schema — but it writes nothing, so it is only a review aid.

## State

The read API (#15) and the publish endpoint (#16) are deployed and live at
`https://flashbeat.rebuildup.dev`; the studio reads the published catalog from
`/api/v1/catalog` and publishes into the same D1. `/?state=loading|empty|error`
forces a list state so every branch of the panel can be reviewed without a backend.

See `AGENTS.md` for the layout, the commands and the three manual fixes
`@park-ui/cli@1.0.1` needs for the Panda v2 API.
