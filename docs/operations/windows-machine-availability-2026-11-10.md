前回「Mac から展示 PC への remote 経路は文書化されていない (Herdr はローカル専用)」と
報告したが、**これは誤り**。実際には Herdr に Windows 機が登録されており、SSH で到達できる。

| 項目 | 実測値 |
|---|---|
| `herdr machine list` | ラベル **Windows** (`target: device-windows`, session `default`, enabled) と **Ubuntu (WSL)** (`device-wsl`) |
| `herdr machine status Windows` | **`reachable`** (error なし) |
| SSH 定義 | `~/.ssh/devices.conf` の `Host device-windows` → `100.118.123.62:22222` / user `basic` / `id_ed25519_devices` (Tailscale 網) |
| 到達性 | `nc -z 100.118.123.62 22222` → **open** |
| SSH ログイン | 成功。リモートの既定シェルは **cmd.exe** (Unix 風の `hostname` は Git for Windows のものが先に当たる) |

つまり **「接続できるか」の答えは「できる」**。前回の「経路が無い」は撤回する。

## 3. 安全な検証方法 (提案 / 実行はオーナー許可後)

この Windows 開発機は **受入の代用にはならないが、Windows 固有の欠陥を潰す足場にはなる**。

| 受入項目 | この機で可能か | 理由 |
|---|---|---|
| Win64 ビルドが起動する / クラッシュしない | **可能** | 実 Windows (DX11) |
| Media Foundation で映像が読める (`WindowsVideoMedia error 0x80070005` の再現・修正確認) | **可能** | Windows 固有。ここで直せれば展示 PC の負担が減る |
| ノーツ・映像が見える (#233) / 音声が鳴る (#13) | **可能 (画面キャプチャ)** | ただし GPU が違う (RTX 4050 / Iris Xe) |
| 1024×768 / 1920×1080 / 2560×1440 の 3 解像度 | **2560×1440 は実ディスプレイで可能**。1920×1080 はこの機のパネルに無い | 3 解像度の証拠規則 (実ディスプレイ全画面) を満たせるのは 2K のみ |
| 展示 PC での最終受入 (#242) | **不可** | 会場の実機・実環境が違う |

**手順案 (オーナーが「この機でやってよい」と決めた場合のみ)**

1. 独立した場所へ展開する: `D:\FlashBeat-acceptance\7af9242d\`
   (既存のどのディレクトリにも触らない。ZIP は 275 MB / 展開後 ~700 MB 程度)。
2. 実行前に **その機で herdr / エージェント作業が動いていないこと**を確認する
   (現在 4 プロセスが常駐しているため、勝手に始めない)。
3. 起動は **オーナーまたはオーナーの指示を受けた人が行う**。cc は
   起動後のログ (`Player.log`) と画面キャプチャの **回収と解析** を担当する。
4. キー入力の自動化 (autotest ハーネス) は、**展示 PC では絶対に使わない**。
   この開発機で使う場合もオーナーの明示的な許可を前提にする
   (2026-11-07 の事故は「一括 `Stop-Process` で稼働中の展示アプリを落とした」もの)。

**現時点で cc が実行してよいこと**: 読み取り専用の状態確認 (済み)。
**実行してはいけないこと**: アプリの起動、プロセスの停止、キー入力の送出、
既存ディレクトリへの書き込み、展示 PC への接続。
