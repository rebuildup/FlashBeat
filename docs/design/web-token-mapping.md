# Web token mapping — Pen v5 → Panda CSS / Park UI (issue #60)

Source of truth: `design/flashbeat-ui.pen` (variables + `Prefab/*` component layers).
Target: `web/panda.config.ts` + `web/src/theme/colors/**` (Park UI shaped palettes).
Date: 2026-11-07 · branch `60`.

Pen v5 defines named colors, five neutral ramps and status triples — **not** 12-step
ramps. Park UI palettes need steps 1–12 + alpha steps `a1–a12` + the semantic pairs
`solid / subtle / surface / outline / plain`. This document records, per Panda step,
whether the value is a **Pen anchor** (verbatim) or **derived** (hue-consistent
interpolation around the anchor hue; deterministic, regenerated by the script excerpt
at the bottom, never hand-tuned).

## 1. Neutral ramp (`gray`, replaces Park `slate`)

Pen ramp relationships: `well #131313` (recessed containers) < `bg #1B1B1B` (canvas)
< `base #2D2D2D` (raised controls) < u1–u5 (raised hierarchy) with text at
`text #FFFFFF` / `text-muted #B0B0B0` / `text-dim #8C8C8C`.

| Panda step | Dark (used) | Source |
|---|---|---|
| 1 | `#131313` | Pen `well` — recessed surface (panels, list wells) |
| 2 | `#1B1B1B` | Pen `bg` — canvas (semantic `canvas`) |
| 3 | `#202020` | Pen `g2` |
| 4 | `#262626` | Pen `g3` |
| 5 | `#2A2A2A` | Pen `g4` |
| 6 | `#2D2D2D` | Pen `base` — raised control fill |
| 7 | `#353535` | Pen `g7` |
| 8 | `#3E3E3E` | Pen `g8` ≙ `r2` (secondary control fill `#3A3A3A` range) |
| 9 | `#4A4A4A` | Pen `g11` — disabled/solid-neutral fill |
| 10 | `#8C8C8C` | Pen `text-dim` → semantic `fg.subtle` |
| 11 | `#B0B0B0` | Pen `text-muted` → semantic `fg.muted` |
| 12 | `#FFFFFF` | Pen `text` → semantic `fg.default` |

Semantic tokens: `canvas` = `gray.2` (`#1B1B1B`, Pen `bg`); `border` dark = `gray.6`
(hairline on canvas ≈ 1:0.7 luminance step; Pen control borders `#5C5C5C` are applied
per-component by raised recipes, not as the global hairline). Light column is a derived
inverted ramp — the studio is dark-first (`color-scheme: dark`), light values stay
defined only because Park semantic tokens require both modes.

Not translated (Pen-only): `d1–d4`, `u1–u5`, `k0–k6`, `overlay`, `deep` — they are
Unity-scene layer ramps; the Web equivalents are `gray.1–6` + component recipes.
`r1–r3` ≈ `gray.7–8` range (secondary control fills).

## 2. Accent (`blue`, replaces Park `teal` `#12A594`)

Pen anchors: `accent #3FA9F5` (hue ≈205°), `accent-tint #2B4457`, `accent-light #9AD3FA`.

| Panda step | Dark | Source |
|---|---|---|
| 9 | `#3FA9F5` | **Pen `accent`** (solid bg, focus ring) |
| 10 | `#5CB6F7` | derived hover (accent hue, lightness +6) |
| 11 | `#9AD3FA` | **Pen `accent-light`** (accent as text, selected fg) |
| 12 | `#C1E3FC` | derived near-white emphasis |
| 1–8 | `#0D1114`…`#156BA8` | derived hue-205 ramp (canvas-adjacent → mid) |

Pen usage evidence: accent is **never a filled button** — `Prefab/Button Primary` is
`#EDEDED` with `#1B1B1B` text; accent fills appear on `Tag NEW` chips (text `$bg`
#1B1B1B, contrast 7.3:1), icons, and selected/active states. Therefore:

- `blue.solid.fg` dark = `#131313` (dark-on-accent, per Pen Tag NEW; 7.3:1) — not white.
- gray `solid` keeps the Park inversion (white bg + black fg dark) = Pen primary button.
- subtle/surface bg = `blue.a3/a2` ≈ Pen `accent-tint` (rgba accent α≈0.14–0.17 over
  canvas ≈ `#2B4457`; verified blend below).

Pen alpha usage found in file: `#3FA9F533/59/66/A6` (α 0.2–0.65) — matches the alpha-step
approach rather than solid tint steps.

## 3. Status palettes (`red`, `green`, new `amber`)

| Panda palette | Pen anchors | step 9 (dark) | step 11 (dark, text-safe) | Pen tint ≙ subtle bg |
|---|---|---|---|---|
| `red` | `danger` / `danger-light` | `#FF6B6B` | `#FFA8A8` | `#4D3232` ≙ rgba(255,107,107,.17) over canvas |
| `green` | `ok` / `ok-light` | `#4CC38A` | `#8FE0B8` | `#2B4A3C` ≙ rgba(76,195,138,.17) over canvas |
| `amber` (new) | `warn` / `warn-light` | `#E9B949` | `#F4D88A` | `#4A4029` ≙ rgba(233,185,73,.17) over canvas |

All colored solid fills take **dark** fg (`#131313`) in dark mode — white on
`#FF6B6B/#E9B949/#4CC38A/#3FA9F5` is 1.8–2.6:1, dark text is 6.7–10:1. Light mode keeps
white fg on the darker light-mode 9s (≥3.6:1).

Contrast checks (dark surfaces):
- `fg.default #FFFFFF` on canvas `#1B1B1B`: 17.9:1 · on recessed `#131313`: 19.9:1
- `fg.muted #B0B0B0` on canvas: 9.9:1 · `fg.subtle #8C8C8C` on canvas: 5.5:1
- accent text `#9AD3FA` on canvas: 10.2:1; focus ring `#3FA9F5` vs canvas: 2.5:1
  (non-text UI element ≥3:1 target → ring draws at 2px + 2px offset; flagged residual,
  see §6).

## 4. Typography

Pen: `font-ui` = `font-num` = `Noto Sans JP`. Web: self-hosted
`@fontsource-variable/noto-sans-jp`, stack `"Noto Sans JP Variable", "Noto Sans JP",
"Hiragino Kaku Gothic ProN", "Yu Gothic", system-ui, sans-serif` (global body).
Pen component sizes (1920 canvas) ÷2.4 ⇒ web scale anchor: row title 30px→sm/500,
secondary 22px→xs/400. Numeric values use tabular-nums (already applied by list cells)
to satisfy font-num parity. `2xs` remains in the scale but screen issues (#70+) audit
every usage for readability.

## 5. Component layer translation (Pen → Park roles)

| Pen layer | Pen evidence | Web role |
|---|---|---|
| Raised controls (Button Primary `#EDEDED`/dark text; Secondary `#3A3A3A`) | `Prefab/Button*` | gray `solid` (inverted), `gray.8` surface fills; radius `l2` (pen radius 8) |
| Recessed lists (`List (recessed)`, rows in wells) | SongRow height 72, radius 8 | panel/list bg `gray.1` (`well`), hairline `border` separators |
| Accent chips/tags (`Tag NEW` accent bg, `$bg` text) | Tag NEW | `blue.solid` chip or `blue.subtle` text chip |
| Selected state (accent-light text on accent-tint bg) | nav/selected nodes | `blue.subtle.bg` + `blue.11` fg |
| Status (danger/warn/ok + tint/light) | status variables | `red`/`amber`/`green` `subtle` (bg tint + light fg), solid for destructive confirm |
| Focus | pen focus ring accent | `--global-color-focus-ring` = `blue.9` (`#3FA9F5`) |

State meaning is not color-only: Park recipes pair bg changes with fg/border changes
(subtle: bg α-step + fg step 11); destructive/error additionally carry icon/text labels
at component level (#70/#72/#73 responsibility).

## 6. Residual deviations (accepted, recorded)

1. Steps 1–8 of `blue`/`red`/`green`/`amber` (dark) and the whole light-mode columns are
   derived interpolations — Pen defines only anchor values. Deterministic generator, see below.
2. Focus ring contrast 2.5:1 vs 3:1 non-text minimum — accent is Pen-fixed; ring offset
   keeps it perceivable; revisit only if #74 accessibility audit fails it.
3. `bg #1B1B1B` vs `g1 #1A1A1A` are near-duplicates in Pen; web keeps both as gray.2/gray.1
   roles (canvas vs raised-adjacent) without merging, per token-audit "normalize without
   flattening".

## Regeneration script

Palettes were generated (`steps 1–8` hue interpolation + anchors) with a one-shot script;
the committed TS files are canonical. To regenerate a ramp, re-derive with:
hue fixed per palette (gray: none; blue 205, red 0, green 151, amber 44), dark L 6.5→37%
for 1–8, anchors at 9 (`$pen`), 10 (`pen hue, L+6`), 11 (`$pen-light`), 12 (`pen-light hue, L+8`);
alpha ramp `04 07 0e 17 1f 29 38 4d 66 73 85 94` (dark) from step-9 RGB.
