# #222 — ドットレールの曲数上限 (設計課題 / 展示版の UI は変更しない)

**状態: 設計課題として保留。実装しない (2026-11-10)。**
オーナー指示: 「54 曲はドットレールの**現行レイアウトの上限**であり、カタログ機能の上限とはしない。
展示版の UI は変更せず、55 曲以上でもレールがはみ出さず、すべての曲へ到達できる表示方式を
設計課題として残す。既存の 60 件合成カタログテストは保持する。」

---

## 1. 何が起きているか (実測)

選曲画面のドットレールは **1 曲 1 ドット** で、`V6SelectView.BuildDots` が
リストパネル内の `y = DotY = 136` に、高さ `DotBottom(count, 0f)` のコンテナを置く。
ドットの刻みは `DotSize(8) + DotGap(4) = 12`、パネル下端は `ListH = 780`。

```
下端 = 136 + (count - 1) * 12 + 8
54 曲 → 136 + 636 + 8 = 780   (ちょうど収まる)
55 曲 → 792                   (12 px はみ出す)
60 曲 → 852                   (72 px はみ出す)
```

固定しているテスト: `Assets/Tests/Editor/SongCatalogScalabilityTests.cs`

| テスト | 内容 |
|---|---|
| `DotRail_FitsInsideListPanel_ForRequired45Songs` | 要件の 45 曲は収まる |
| `DotRail_DesignGeometry_HoldsUpTo54Songs` | 上限 = 54 曲 / 60 曲でははみ出すことを明示 |
| `DotRail_SpacingIsDotSizePlusGap_AndActiveIndexClamps` | 刻み = `DotSize + DotGap`、アクティブ index のクランプ |
| `SyntheticCatalog_HasAtLeast45Songs_AndIsWellFormed` ほか | 60 件の合成カタログ全体 (検索 / スクロール / Ready) |

**カタログ機能そのものは 54 曲で止まらない**: 検索・スクロール・`ScrollToReveal`・
`ReadyAvailable` は 60 曲でも全曲到達可能であることを同じテストが固定している。
上限は **レールという表示部品だけ** の制約。

現状の実カタログは 29 エントリ / 選曲可 26 なので、**展示 (11/14) では発生しない**。

## 2. 制約 (設計するときに守るもの)

| 制約 | 内容 |
|---|---|
| 展示版を変えない | 11/14 の展示候補 (`7af9242d`) の UI を変えない。設計は展示後 |
| デザイン正本 | 1 曲 1 ドットのレール (design `AqFtx` / `OENRv`)。勝手に別部品に置き換えない |
| 現在位置の可視性 | 「一覧のどこに居るか」が一目で分かること (レールの存在理由) |
| 全曲到達 | どの曲もスクロール / 検索 / 曲送りで到達できること (既に充足) |
| タッチ・マウス | 展示はキーボード中心だが、レールはクリック対象になり得る |

## 3. 選択肢 (実装しない。比較だけ)

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| A. ドットを縮める | `DotSize` / `DotGap` を曲数に応じて縮小 | 部品はそのまま | 60 曲で 1 ドット ≈ 8 px を割り、視認・クリックが難しい。90 曲で破綻 |
| B. 間引く | 全曲ではなく「代表ドット + 現在位置マーカー」 | 見た目が安定 | 「全曲の位置」が分からなくなる。契約 (1 曲 1 ドット) の変更 |
| C. 2 列 / 複数列 | 54 曲で折り返す | 曲数に比例して伸びる | パネル幅 (`ListW=560`) の余白が要る。折り返し位置の規則が必要 |
| D. 窓付きレール | 54 曲分だけ表示し、現在位置に応じてレール自体をスクロール | 見た目は現状維持 | 「全体のどこか」が分かりにくい。実装はスクロール同期が要る |
| E. 割合バー + 現在位置 | ドットをやめ、細いバーとマーカー | 曲数無制限 | デザイン正本の変更。展示後の再設計として扱う |

**推奨 (展示後)**: まず C か D を、design 正本の更新とセットで決める。
A は 60 曲でも可読性が落ちるため採らない。B / E は「1 曲 1 ドット」の契約を変えるので、
#218 (デザイン契約) の更新を伴う。

2. 55 曲以上が必要になったとき、どの案で行くか (C / D / E)
3. design 正本 (`AqFtx` / `OENRv`) の更新を誰が行うか
