## 3. 未確定 (オーナー決定が必要 — 実装担当が確定しない)

**どの項目も「保留」であり、要件の削除ではない。** 影響する Issue が止まらないよう、
代替の既定値を明記している (既定値は **実装禁止**。決定されるまで触らない)。

### D1 — 歌詞の正式データ形状と移行方針

- **質問**: 新しい正式な歌詞データを `lyrics?: [{ startMs, endMs, text }]` 形式に統一し、
  既存 `lyrics:{startTime,mondai,endTime,furigana,romaji}` と `*_text.json` を
  段階的にどう移行するか。
- **選択肢**: (a) 既存ブロックを正本のまま使い続ける (b) 新形式を正本にして読み込み互換のみ残す (c) 新旧両方を正本として保持
- **推奨**: (b) — Web エディタは読み込み互換を持ち、Unity は新形式を優先して読む
- **波及**: #59 の歌詞同期行 / #3 の契約 (#30 §6) / Web 譜面エディタ / 公開 API の互換
- **代替既定値 (決定まで)**: 既存ブロックを正本のまま扱う。**新形式の実装は開始しない**
- **期限**: 展示前 (11/14) には「公開契約として固定したか」だけ決めたい

### D2 — 歌詞の表示仕様

- **質問**: 1 行 / 複数行の別、間奏中 (歌詞なし区間) の表示、歌詞が無い曲の HUD レイアウト
- **推奨**: 複数行可。1 曲分を時刻ベースで扱い、間奏中は直前の歌詞を保持せず非表示。歌詞が無い曲子では歌詞領域ごと非表示 (余白を残さない)
- **波及**: #59 の歌詞同期行 / v6 HUD レイアウト (#223 / #240)
- **代替既定値**: 現状の v6 HUD の歌詞表示をそのまま使う

### D3 — キーガイド (全キー案内) の仕様

- **質問**: ガイドの表示位置・開閉操作・JIS/US キーマップ差・本番デフォルト
- **推奨**: 選曲画面やポーズの中に「全キー」をフル表示し、プレイ中はコンパクト表示。キーマップは `KeyBindings` の実定義から生成 (JIS/US の差もそこから)
- **波及**: #59 のキーガイド行 / #167 / #224 (ポーズ) / v6 Select (#221)
- **代替既定値**: 現状の `KeyGuideUI` の表示 (コンパクト) をそのまま使う

### D4 — pen.dev デザイン正本の参照

- **質問**: 実装対象とする .pen ファイル / フレームの参照と、画面ごとの実装優先順位
- **推奨**: Issue #30 のコメントに .pen の file 名と frame 名 (07b Pause / 07c Loading / OENRv Select など) を貼る。**憶測で新規デザインを創作しない**
- **波及**: #224 / #221 / #240 の見た目の最終形
- **代替既定値**: 既存 Unity UI (Pen の差分が未確定) のまま

### D5 — HOLD 混在譜面のランキング記録の分離 (`scoringVersion`)

- **質問**: HOLD はタップと同一配点で凍結済みだが、**採点バージョンを分けるか**は
  #164 の除外事項のまま残っている
- **推奨**: `chartVersion` に加えて `scoringVersion` を scoring 側で持つ (ただし HOLD は同一配点なので影響は小さく、Tap のみ譜面との混在回避が目的)
- **波及**: #21 / #22 (ランキングと release gate) / #59 の HOLD 行の記録部分
- **代替既定値**: 現状の recording 方式 (HOLD が Tap と同点なのでTap のみ譜面との区別は理屈上不要)

### D6 — ふりがな / ローマ字の既存データ

- **質問**: 「新しい正式な歌詞データから `furigana`・`romaji` を削除する」方向は確定済みだが、
  **既存の 27 曲ぶんの歌詞データから削除するか** (旧 `_text.json` / 旧 `lyrics` ブロック) が未確定
- **推奨**: 既存データは壊さない (読み込み互換のみ)。新しい歌詞データを作る/generated な経路では `furigana`/`romaji` を作らない
- **波及**: #59 の歌詞同期行 / Web 公開の互換 / 旧 `_text.json` の移行 (commit `14e3422` で統合済み)
- **代替既定値**: 既存データを保持し、新形式では作らない (削除しない)
